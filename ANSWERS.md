# Відповіді на контрольні питання (Варіант 15)

## 1. Який вид з'єднання (або яку конструкцію) ви обрали і чому саме його?
Було обрано ланцюжок лівих зовнішніх з'єднань (`LEFT JOIN`): `hall` до `workout` за `w.hall_id = h.id`, а потім до `booking` за `b.workout_id = w.id`.
Цей вибір зумовлений вимогою зберегти всі зали з таблиці `hall`, зокрема ті, які наразі не мають закріплених тренувань (`workout`), а також ті тренування, які не мають жодного бронювання (`booking`). Внутрішнє з'єднання (`INNER JOIN`) відсіяло б такі зали з вибірки.

## 2. Як ви переконалися, що в результаті немає розмноження рядків і не втрачено рядки з NULL або без пари?
- **Уникнення розмноження рядків:** При каскадному з'єднанні один-до-багатьох (`hall` -> `workout` -> `booking`) для кожного тренування створюється стільки рядків, скільки є пов'язаних записів бронювання. Якщо рахувати тренування звичайною функцією `count(w.id)`, їхня кількість штучно завищиться через повтори. Тому для підрахунку унікальних тренувань застосовано `count(DISTINCT w.id)`. Для підрахунку записів бронювання використано `count(b.id)`, який не враховує `NULL`-значення для залів без бронювань.
- **Обробка рядків без пари та NULL:** Для обчислення суми місць застосовано `coalesce(sum(b.places), 0)`, що замінює результуючий `NULL` на `0` для залів без бронювань відповідно до вимог завдання. Групування виконано за первинним ключем та назвою (`GROUP BY h.id, h.name`).

## 3. Що зміниться в результаті, якщо умову з ON перенести у WHERE (або навпаки) у вашому запиті?
Якщо умову з'єднання (наприклад, `ON w.hall_id = h.id` або будь-яку фільтруючу умову для правої таблиці) перенести у блок `WHERE`, логіка `LEFT JOIN` перетвориться на `INNER JOIN`. 
Оскільки для залів без відповідників стовпці правої таблиці заповнюються значеннями `NULL`, будь-яке пряме порівняння або перевірка у `WHERE` поверне `NULL` (unknown), і такі рядки буде відфільтровано. В результаті з фінального звіту зникнуть зали без тренувань або бронювань.
